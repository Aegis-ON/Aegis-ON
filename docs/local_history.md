# 로컬 분석 및 승인 시뮬레이션 이력

기본 파일은 `~/.aegis-on/history.sqlite3`이다. 시작 전에 `AEGIS_HISTORY_DB`에 저장소 밖의 파일 경로를 설정해 변경할 수 있다. 기본 파일은 첫 조회 또는 분석 시 생성된다. 예: `export AEGIS_HISTORY_DB="$HOME/aegis-private/history.sqlite3"`. 서버를 재시작해도 같은 파일과 설정을 사용하면 인증 후 대시보드의 **로컬 분석 이력** 또는 `GET /api/v1/history`로 조회할 수 있다. `GET /api/v1/detections`와 기존 승인 API도 유지된다. 분석 응답에는 추가 필드 `analysis_id`가 있다. 이력 API에서 `analyses[].detection_ids`와 `detections[].detection_id`, `event_refs` 및 `source_events`의 식별자를 연결한다. 기존 JSON 입력의 사용자 제공 이벤트 ID는 저장 시 별도 가명으로 바뀌므로 원본 입력의 `input_index`와 함께 비교한다.

## 저장 범위와 개인정보

- 분석 ID 및 시각, JSON/Sysmon 유형, 처리·오류·미지원 수, 가명처리 후 이벤트 인덱스·식별자·출처와 Sysmon 연결 메타데이터(레코드 및 프로세스 식별자, IP/포트, 시각, 방향 등)를 저장한다. IP와 기타 후보는 기존 가명처리를 거치고 호스트와 JSON 이벤트 ID는 추가 가명처리한다.
- 탐지 ID, 유형, 심각도 점수, 출처(규칙·키워드·상관), 근거와 연결 이벤트 ID, 공격 분석 모델 상태·가중치 해시·분류 결과와 개인정보 모델 상태를 저장한다. JSON 규칙의 명령 일부 및 프로세스 경로가 근거로 복사되지 않도록 저장 시 제거한다.
- 최초 승인 시각, 가명처리된 분석가·사유와 `simulation_only`를 저장한다. 승인은 **실제 차단이나 외부 시스템 연동이 아니다**. 원본 로그, 전체 명령줄, PII 후보 원문 목록, 모델 파일과 설정된 인증 토큰을 저장 목적으로 수집하지 않는다.
- 가명처리는 완전하지 않고 모델 미탐이나 예상하지 못한 입력은 식별 정보·자유 입력 사유 등에 남을 수 있다. 비밀번호, API 키, 인증 토큰 등 비밀값을 승인 사유나 식별 정보에 넣지 말 것. 알려진 토큰과 일부 `password=...`, `token=...` 형태는 추가 마스킹하지만 모든 비밀을 탐지하지는 못한다. 이력은 익명 데이터가 아니며 암호화되지 않는다. 접근을 신뢰할 수 있는 로컬 사용자로 제한한다.
- `AEGIS_PII_VERIFIED_PUBLIC_HOSTS`에 운영자가 예외로 지정한 호스트는 해당 호스트의 표시용 대체값을 DB에 저장할 수 있다. 예외가 유지되는 동안 관련 탐지 API에서 표시될 수 있으므로 민감한 호스트에 사용하지 않는다. 예외를 제거하면 이력은 보수적 호스트 가명을 반환하지만 기존 DB와 백업에 남은 대체값은 자동 삭제되지 않는다.
- 호스트·JSON ID 가명은 고정된 공개 salt를 사용한 짧은 해시이므로 추측 공격에 취약하며 암호학적 익명화가 아니다. 최초 응답과 저장 이력의 JSON ID는 다르므로 `analysis_id`와 `input_index`로 원본 위치를 연결한다.

## 파일, 충돌 및 실패

새 디렉터리에는 가능한 경우 소유자 전용 권한(0700), DB에는 0600을 사용한다. POSIX에서 기존 DB가 그룹·다른 사용자에게 접근 가능하거나 DB 경로 자체가 심볼릭 링크면 사용을 거부한다. 기존 디렉터리 권한은 바꾸지 않으므로 운영자가 상위 디렉터리와 백업 권한을 확인해야 한다. Windows에서는 파일 ACL을 운영자가 확인·제한해야 한다. SQLite 잠금은 같은 로컬 파일을 쓰는 여러 프로세스 사이에서 최초 승인을 직렬화한다. 잠금 대기 시간이 초과되거나 저장소가 손상되면 503이며 분석 전체는 커밋되지 않는다. 네트워크 파일시스템에서 잠금 동작은 보장하지 않는다.

스키마는 SQLite `PRAGMA user_version=1`이다. 빈 DB를 자동 생성하고 지원하지 않는 버전 또는 손상된 DB는 열지 않는다. 실행 중 이미 연 파일이 삭제·교체되면 오류로 처리한다. 다만 서버가 종료된 동안 파일이 사라진 경우는 첫 실행과 구분할 수 없으므로 운영자가 백업을 유지해야 한다. 현재 자동 마이그레이션은 없으며 미래 버전의 마이그레이션 제공 전에는 기존 DB를 백업하고 변경하지 않는다. 파일을 옮기기 전 서버의 모든 프로세스를 종료한다. 백업에도 동일한 접근 제한을 적용한다. 삭제하려면 서버를 종료한 뒤 DB와 남은 `-journal`, `-wal`, `-shm` 파일 및 백업을 삭제한다. 파일 삭제가 매체에서의 안전한 완전 삭제를 보장하지는 않는다. 별도 보존 기간과 자동 삭제는 구현되지 않았다.

Docker의 기존 `--rm` 예제는 컨테이너 내부 DB가 컨테이너 삭제 시 사라진다. 영속성을 원하면 사전에 접근을 제한한 호스트 디렉터리를 준비하고 해당 디렉터리를 볼륨으로 마운트한 후 `AEGIS_HISTORY_DB`를 그 안의 경로로 설정한다. 컨테이너 UID가 쓸 수 있어야 한다.

## 검증 범위

실제 Windows 및 Sysmon 검증은 아직 수행하지 않았다. Windows 수집 검증은 별도 Draft PR #9에서 추후 진행한다. 실사용 로그를 저장소, Colab 또는 외부 서비스로 전송하지 않는다.
