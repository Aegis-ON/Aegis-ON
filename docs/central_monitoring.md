# 중앙 관제 설정과 보안 범위

Aegis-ON은 분석가 한 명을 운영자가 설정하는 실험용 관제 서버입니다. 회원가입·다중 사용자·역할 관리는 없습니다. 서버는 이벤트 전체나 전체 명령줄을 영구 저장하지 않으며 가명처리된 연결 정보·근거·승인 시뮬레이션 이력을 SQLite에 보관합니다. 모델이 놓친 개인정보나 비밀값이 남을 수 있습니다. PII NER과 공격 분석 BERT는 별도의 선택 기능이며 공격 모델은 실험용입니다. 승인은 실제 차단이 아닙니다.

## 서버와 분석가 계정

격리된 신뢰 환경에서 의존성을 설치합니다. 운영자는 아래 명령에서 12자 이상의 비밀번호를 숨겨 두 번 입력하고 출력된 scrypt 해시만 제한된 서버 설정에 보관합니다. 비밀번호 평문을 환경 변수, 셸 히스토리, 저장소에 기록하지 마세요.

```bash
python -m pip install -r requirements.txt
PYTHONPATH=src python -m aegis_on.auth_sessions hash-password
# 아래 해시는 위 명령의 출력으로 바꿉니다. $ 확장을 막기 위해 작은따옴표를 유지합니다.
export AEGIS_LOGIN_USERNAME='analyst'
export AEGIS_LOGIN_PASSWORD_HASH='여기에_출력된_scrypt_해시'
export AEGIS_ANALYST_NAME='analyst'
export AEGIS_HISTORY_DB='/서버의_비공개_경로/history.sqlite3'
export AEGIS_AUTH_DB='/서버의_비공개_경로/sessions.sqlite3'
PYTHONPATH=src uvicorn aegis_on.api:app --host 127.0.0.1 --port 8000
```

브라우저에서 `http://127.0.0.1:8000/`을 열어 로그인합니다. 로그인 세션은 서버 측 만료(기본 3600초, `AEGIS_SESSION_TTL_SECONDS` 60~86400)·로그아웃·비밀번호 해시 변경으로 무효화됩니다. 비밀번호는 scrypt, 세션과 수집기 비밀값은 고엔트로피 난수의 SHA-256 검증값만 저장됩니다. 쿠키는 HttpOnly/SameSite=Strict이며 HTTPS에서 Secure입니다. 상태 변경은 CSRF 토큰을 확인합니다. 인증 DB와 SQLite 보조 파일에도 접근을 제한하세요.

서버를 원격 사용하려면 신뢰된 HTTPS 종단과 방화벽을 별도로 구성하고 ASGI 서버가 **신뢰하는 프록시에서만** 원래 HTTPS 방식과 클라이언트 주소를 받도록 설정해야 합니다. 비로컬 HTTP 자격 증명 요청은 거부합니다. 운영 프록시에서 로그인 속도 제한을 설정하세요. 앱의 제한은 프로세스별 60초당 주소별 10회, 동시 비밀번호 검증 2건으로 여러 서버 전체의 분산 제한은 아닙니다. 프록시 신뢰 범위를 잘못 설정하면 TLS·주소 확인이 무력화될 수 있습니다. 프로토타입이므로 인터넷에 직접 공개하거나 운영 배포하기 전에 별도 보안 검토가 필요합니다.

기존 `AEGIS_API_TOKEN`과 `AEGIS_ANALYST_NAME`은 자동화 API의 Bearer 인증으로 유지됩니다. 브라우저는 API 토큰 입력 없이 로그인합니다. 공유 토큰은 전체 분석가 권한이므로 안전하게 보관하고, 수집기 등록에는 브라우저 세션을 사용합니다.

## PC별 등록과 확인

관제 개요 또는 엔드포인트 화면에서 `pc-01` 등 임의의 ID를 등록하면 일회성 자격 증명을 복사할 수 있습니다. 비밀값은 화면에 표시하지 않으며 클립보드 복사에는 브라우저가 지원하는 보안 컨텍스트가 필요합니다. 복사하지 않고 닫으면 폐기 후 재발급해야 합니다. 등록 전 기존 공유 토큰으로 관찰된 ID는 새 PC에 자동 귀속하지 않으며 다른 ID를 골라야 합니다. 등록된 수집기는 아직 이벤트가 없어도 목록에 나타납니다. 각 PC에 별도의 비밀값을 설정하고 [지속 수집 문서](continuous_collection.md)의 Windows 절차를 따르세요. 서버와 수집기를 연결하는 네트워크나 인증서는 자동 생성하지 않습니다.

수집기는 ID와 비밀값을 함께 보내며 다른 ID를 사칭할 수 없습니다. 수집기 자격은 분석가 이력 조회 권한이 아닙니다. 호스트 이름은 수집기 ID와 함께 관찰 단위로 묶고, 이벤트가 없거나 이름이 같아도 서로 다른 물리 장치를 확정하지 않습니다. 상태는 마지막 수집기 보고이지 PC 온라인 여부가 아닙니다. 식별자·이벤트 해시·가명도 민감할 수 있습니다.

### 인증 정보 폐기·재발급

관제 개요 또는 엔드포인트 화면의 수집기 목록에서 활성 ID의 **폐기**를 누르면 이후 인증 확인에서 이전 수집기 비밀이 거부됩니다. **재발급**은 폐기 상태에서만 가능하며 같은 ID와 기존 이벤트·탐지·승인 이력은 유지됩니다. 새 비밀은 일회성으로 복사할 수 있고 서버에는 SHA-256 검증값만 저장됩니다. 새 비밀은 해당 Windows PC에 안전한 경로로 전달하세요. 동시 재발급 중 한 요청만 성공하며 나머지는 충돌(409)합니다.

레거시 공유 토큰 허용을 켜더라도 등록 이력이 있는 활성·폐기 ID는 개별 비밀만 허용합니다. 미등록 레거시 ID는 호환 설정이 켜진 동안 공유 토큰을 사용할 수 있으므로 장기적으로 설정을 끄세요. 폐기 기록은 우회를 막기 위해 삭제하지 않습니다. 기존 v3 DB에 인증 변경 시각을 별도 테이블로 추가하며 기존 자격 및 이력은 유지됩니다. 업데이트 전 DB와 보조 파일을 백업하세요.

수집기를 중지하고 같은 실행 계정에서 **새 파일 경로**로 `-InitializeCredential`을 실행해 새 비밀을 숨겨 입력합니다. 기존 파일은 덮어쓰지 않습니다. 이후 같은 `CollectorId`, `ServerUrl`, `CursorPath`와 새 `CredentialPath`로 수집기를 재시작합니다. 기존 cursor·binding·pending 파일을 보존하세요. 구체적 명령은 [지속 수집 문서](continuous_collection.md)를 확인하세요. 응답이 유실돼 새 비밀을 확인하지 못했다면 목록을 새로고침하여 상태를 확인하고 다시 폐기→재발급합니다. 비밀은 서버에서 복구할 수 없습니다.

**동시 요청 한계:** 인증 검증과 이벤트 저장·heartbeat 기록은 별도 트랜잭션입니다. 폐기·재발급 전에 인증된 요청은 그 후에도 완료될 수 있습니다. 표시되는 변경 이후 보고도 이전에 인증된 요청일 수 있어 새 비밀 적용을 증명하지 않습니다. 강제 차단이 필요하면 수집기와 네트워크 경로를 중지하고 진행 중 요청이 끝났는지 확인하세요. 마지막 보고 시각은 서버에 도달한 마지막 보고이며 서버가 받지 못한 오류와 PC의 실제 온라인 여부는 알 수 없습니다. 과거 마지막 오류는 현재 상태와 별도로 표시합니다.

## 검증 범위와 손실 가능성

두 가상 수집기의 인증·분리·이력 재조회 및 Sysmon 동일 이벤트 재전송은 테스트합니다. JSON 수집은 같은 배치 키 재시도만 중복 제거합니다. Sysmon 커서 진행·재시도·롤오버 한계는 [지속 수집 문서](continuous_collection.md)를 참조하세요. 실제 Windows에서 DPAPI, PowerShell 실행, Sysmon Event ID 1·3, TLS, 서비스 계정, 재부팅, 장시간 중단·로그 롤오버는 아직 검증되지 않았습니다. 이 기능은 Draft 상태에서 해당 절차를 실제 Windows에서 확인해야 합니다.
