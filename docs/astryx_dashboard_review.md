# 관제 화면 검토와 Astryx 전환

## 검토 범위

기준은 PR #20의 `5bdc47580d31307c2577401c7755ab7dfaffbc9e`다. Mac 다운로드 폴더의 참고 영상에서 직접 프레임을 추출해 왼쪽 메뉴, 다중 패널, 높은 정보 밀도, 상태 강조를 확인했다. 영상에는 밝은 네온 효과도 있으나 장시간 관제와 사용자의 요청에 맞춰 이를 재현하지 않는다. 영상 속 수치와 실제 연동이 없는 기능은 가져오지 않았다.

독립 코드 검토와 Impeccable 자동 검출에서 우선 확인한 문제:

1. 제목 위 영문 라벨과 격자형 자산 배경 등 장식이 데이터 위계에 비해 강하고, 그라데이션·장식색이 반복된다.
2. 일부 큰 화면에서 최근 탐지의 분석 시각 열이 감춰져 시간 확인이 어렵다.
3. 상태·제한 설명 중 반복이 있으나 수집기 보고와 PC 온라인 여부의 차이, 승인 시뮬레이션, 가명정보의 위험처럼 제거하면 안 되는 안내도 있다.
4. 작은 글자·고밀도와 여러 색이 동시에 사용돼 장시간 사용 시 가독성이 저하될 가능성이 있다. 실제 사용성 시험 결과는 아니다.

## 구현 선택

Astryx `@astryxdesign/core`와 중립 테마 0.7.16을 사용하고 React와 번들을 저장소 내에서 제공한다. 직접 작성한 레이아웃 CSS는 단색 배경과 구분선 중심이다. 심각도에는 색과 텍스트를 함께 사용한다. 표·입력·버튼·선택·대화상자는 Astryx 컴포넌트이며 구조에는 HTML 요소를 사용한다. 기존 이벤트·탐지 이력과 수집기 관리, 인증, 승인 API는 그대로 사용한다. 별도 웹·방화벽 수집을 구현한 것은 아니다.

## 입체 자산판

참고 영상 21초와 30초 부근에서 여러 기울어진 평면 위의 입체 상자와 층간 선을 확인했다. 해당 선을 실제 네트워크 관계로 표현할 근거는 현재 API에 없으므로 그리지 않는다. 검은 바탕의 자산판은 `/api/v1/endpoints`가 반환한 호스트 관찰 묶음 중 최대 6개만 상자로 표시하며, 각 상자는 같은 `endpoint_id`의 상세로 연결된다. 위치와 바닥선은 시각적 배치이고 실제 장치, 연결 관계, 온라인 여부를 뜻하지 않는다. 탐지 점수에 따른 색은 관찰에 연결된 최고 점수의 심각도이며 상태 확정이나 안전 판정이 아니다. 데이터가 없으면 상자를 만들지 않고, 실패 시 오류와 이전 값 여부를 알린다. 색상 외에도 옆 목록에 탐지 건수와 최고 심각도를 표시한다.

영상의 촬영 화면 움직임과 화면 자체의 애니메이션을 이 프레임만으로 분리해 확인할 수 없었다. 따라서 자동 회전이나 지속 애니메이션은 추가하지 않고 선택에 대한 짧은 반응만 제공한다. `prefers-reduced-motion` 설정 시 반응 동작을 없앤다.

보조 API 오류는 각 패널에 알리며 이력 조회를 막지 않는다. 최초 세션 조회 실패는 재시도하고, 느린 갱신은 직렬화하며 요청당 15초 후 타임아웃한다. 표 행의 안정적인 식별자와 React 상태로 열린 상세와 필터를 보존한다. 수집기 자격 증명은 메모리에만 보관하고 화면에 표시하지 않는다. 승인 버튼은 실제 차단을 수행하지 않는다.

이전 `static/console.html` 관련 DOM 테스트는 보존했으나 구 화면을 대상으로 한다. 새 화면 검증은 `frontend/test/dashboard.test.cjs`를 실행해야 한다. 이 검사는 jsdom 기반이며 실제 브라우저의 레이아웃, 포커스, 클립보드를 검증하지 않는다. Windows 수집기와 실제 AI 모델 추론도 이 UI 변경에서 실행하지 않았다.
